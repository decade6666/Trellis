#### 3.2 #469 fallback-session cleanup — MISSING (port candidate)

Fork `clear_active_task` (both dogfood + template, identical):

```python
previous = resolve_active_task(repo_root, platform_input, platform)
context_path = _context_path(repo_root, context_key)  # process key
```

Upstream 0.6.10:

```python
previous = resolve_active_task(...)
if not previous.task_path or not previous.context_key:
    return previous
context_path = _context_path(repo_root, previous.context_key)  # resolved source
```

Behavioral gap (from upstream `script-conventions.md` + 4 regression tests):

1. Exact match → delete only that session (sibling for same task untouched) — fork may already mostly match when keys equal.
2. **Sole fallback** (`session-fallback:<old-key>`) → must delete **old** file, not process-derived current key — **fork fails** (deletes wrong / no-op on wrong path).
3. Ambiguous multi-session → delete nothing — fork may still delete process key file if present.
4. Malformed exact + another session → delete nothing — fork missing `if not previous.task_path` guard.

Tests: `git show d96379a7:packages/cli/test/regression.test.ts` has **no** `[issue #469]` cases. Upstream inserts four tests into the existing session-current-task regression suite (~lines 3933+).

Spec: fork `script-conventions.md` still documents old contract
`clear_active_task (...) | Deletes the current session file`
and
`finish` with context key → deletes `.runtime/sessions/<key>.json`
— not the resolved-source wording.

**Conflict with red lines:** none on package identity. Touch set is dual-mirrored scripts + tests + append-only spec — fits established selective-port pattern. Note: full `active_task.py` fork↔upstream diff also shows **local-only** `kimi`/`snow`/`SNOW_SESSION_ID` platform keys on fork (and upstream has kimi/snow that fork partially lacks in other layers); **must not whole-file checkout** — path-level edit of `clear_active_task` only.

- Research agent on fork **intentionally** runs `task.py current`; upstream forbids it in favor of dispatch `Active task:` / hook payload. Porting #465 semantics means **inserting** a Trellis Context Loading Protocol block **without** removing fork recursion guards or multi_agent pins, and deciding whether research keeps `task.py current` as last-resort (fork) or drops it (upstream).
- `platform-integration.md` on fork is a **large dual-maintained** document (fork vs base stat −421/+170 net shape difference). Upstream 0.6.10 only patches the Codex native SubagentStart subsection (+saved-output rows). Spec sync must be **section-level append/edit**, not file replace.

Risk if skipped: when Codex truncates SubagentStart, fork children may trust a partial marker preview or miss full context; research may still recover via `task.py current` (different failure mode than implement/check).
